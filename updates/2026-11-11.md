## LinkedIn post

Today I wired Android background sending into HoldSend's Expo example. When the app is closed, Android can now run a short task that sends notes written offline, once each, with the same key if a send is cut off.

The lesson came from reading the background library's Android source instead of trusting its type names. Our docs told people to return "failed" so the system would try again sooner. The source shows the value is ignored and the next run is scheduled the same way either way. So the advice was wrong, and I fixed it before anyone relied on it. The screen also says plainly that Android decides when the task runs. It has not been tried on a real phone yet.
