# 2026-11-26

## Done today

- Checks for the server store contract ([#96](https://github.com/zyakuhq/holdsend/pull/96), [decision 0022](../docs/decisions/0022-server-store-contract-checks.md)). HoldSend ships idempotency stores for memory and Postgres. Anyone on MySQL, SQLite or Redis writes their own, and one broken rule there can publish a post twice. Now [test/idempotency-store-contract.ts](../test/idempotency-store-contract.ts) has fifteen checks to copy and run: one of 25 concurrent claims wins, the record and the app's row commit together, a request that lost its claim cannot complete (also when it loses it just before commit), tombstones stay per owner and operation and never expire, and more. Both built-in stores pass. Twenty-six deliberately broken stores each fail the check meant to catch them.
- A separate agent reviewed the checks first. It found that the most important rule, re-checking the claim at commit, was not tested at all, plus four other gaps and a miscount. All fixed. Two rules the stores already kept are now written in the interface's doc comments.
- Yesterday's status update is merged with this pull request; its only red check was a CodeQL upload GitHub refused to retry. Yesterday's docs site deploy hit a GitHub Pages 500 and was re-run.

## LinkedIn post

A test that never fails proves nothing. Today I added checks that anyone can copy to test their own storage layer for HoldSend, our open-source outbox that publishes what people write offline exactly once. The server side keeps a record per request so a retry never creates a second post, and if you run MySQL or Redis you write that store yourself. Before trusting the fifteen checks, I wrote twenty-six deliberately broken stores and made sure each one fails the right check. A second reviewer still found the most important rule untested: a request must lose cleanly if its claim is taken over just before it commits. That gap is closed now. https://github.com/zyakuhq/holdsend
