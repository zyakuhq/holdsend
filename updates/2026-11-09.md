# Update 2026-11-09

## Done today

- `@holdsend/react-native` has `runBackgroundFlush(outbox, { owner, budgetMs })`: one flush with a time limit, made for the callback of an Android background task. It says `done`, `waiting`, `out-of-time` or `failed`, and whether to ask the system to run the task again. Six unit tests, each checked to fail on broken code. README explains the limits: the system decides when the task runs, it may stop it, and nothing is lost or sent twice if it does. Not yet run on a real phone.

## LinkedIn post

Background work on a phone is a promise the operating system makes loosely. Android may run your task every fifteen minutes or not for hours, and it can stop it halfway through a send. This week I added a small helper to HoldSend, our open-source offline outbox for React Native. It runs one flush with a time limit and tells your task whether to ask for another run. The lesson: design for being killed. Each item is claimed before sending, a claim nobody finishes goes stale, and the retry reuses the same key, so a stopped send never becomes two. It is covered by unit tests only so far, and the README says plainly that it has not run on a real phone yet. Repo: https://github.com/zyakuhq/holdsend
