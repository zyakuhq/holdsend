# 0011: What 0.2.0 ships

Date: 2026-11-12. Status: accepted.

## Context

0.2.0 is the emergency-message release (decision 0007). Since that work was finished, `main` also gained the Phase 3 code for one draft on two devices (decision 0009) and `runBackgroundFlush` (decision 0010). `@holdsend/server` imports `@holdsend/core/drafts`, and all four packages share one version, so the draft code cannot be left out of 0.2.0 without removing it from `main` first. The changelog and the package READMEs did not mention drafts at all, so 0.2.0 would have published an API nobody was told about.

## Choice

- 0.2.0 ships everything on `main`: emergency messages, `runBackgroundFlush`, and the draft helpers.
- The draft helpers (`@holdsend/core/drafts` and the draft exports of `@holdsend/server`) are marked "early, for 0.3" in the changelog and the READMEs: they are tested and were covered by a whole-feature audit by a separate reviewer (2026-11-08), but the API may change in 0.3 without a deprecation period.
- The Node smoke test (`scripts/smoke-node.mjs`) loads `@holdsend/core/emergency`, `@holdsend/core/drafts`, the server's draft helpers and `runBackgroundFlush`, and checks that a retried draft update is a replay that adds nothing. CI runs it on Node 20.0.0 against the workspace build; step 5 of [releasing.md](../releasing.md) runs a copy against the packages installed from npm.

## Why

- Removing finished, reviewed code to make a smaller release is work with no gain for users, and it would put `main` and npm out of step.
- Shipping drafts in 0.2.0 also clears the 0.3 blocker in STATUS: `@holdsend/server` needs a core release that has `./drafts`.
- Saying "early" in plain words is more honest than hiding the exports or pretending they are stable.

## Not done

- No version bump yet. Tagging needs the project lead's go-ahead and two approvals (GitHub, then npm with 2FA), as in [releasing.md](../releasing.md).
- Nothing in 0.2.0 has run on a real phone (SMS links, background task). The changelog says so for both.
