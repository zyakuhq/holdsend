# Update: 2026-10-26

## What got done today

- An Expo app for Android and iOS: the notes example on a phone, over `@holdsend/react-native`. Notes wait in AsyncStorage, survive the app being closed, and are never published twice: [examples/expo](../examples/expo).
- Its web build runs in a real browser on every pull request: offline and back, an app restart with notes waiting, a lost answer, cancel, and a note the server refuses. The reconnect test was checked against code that ignores the reconnect signal, and fails as it should.
- Found and worked around a real gap: in a desktop browser, NetInfo does not notice going offline. The web build listens to the browser's own online and offline events instead. Written up in the example's README.
- An independent review found ten issues in the first version (among them a phone setup with no server address silently queuing forever, and a first-launch race that could split one person into two ids). All are fixed.
- Prepared the first release: every package at 0.1.0 with complete npm metadata and its own licence, a check that fails if a package would publish anything but its build output, a CHANGELOG, issue and pull request templates, and a release workflow that publishes with provenance when a version tag is pushed. The `@holdsend` npm organisation and the publish token are in place.
- A third independent audit before the release, by three reviewers working separately, found 31 issues. The ones that mattered most: the server replayed a temporary failure forever, a missing setting could make claims look stale, pages in sandboxed frames never sent anything, and nothing technically required approval before publishing. All the release-blocking ones are fixed, each with a test that fails without the fix: [the report](../docs/audits/2026-10-26-third-audit.md).

- Published 0.1.0 to npm: `@holdsend/core`, `@holdsend/server`, `@holdsend/web` and `@holdsend/react-native`, each with provenance, after the project lead approved it. The first try stopped because the token asked for a one-time password; nothing was half published. Next releases will use npm trusted publishing, with no token at all.
