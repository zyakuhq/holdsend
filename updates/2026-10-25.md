# Update: 2026-10-25

## What got done today

- Read Zyaku's offline publishing design and wrote it up in our own words: [docs/reference-notes.md](../docs/reference-notes.md). No code or data copied.
- Named the project HoldSend (SendOnce was taken on npm and on GitHub) and chose Apache-2.0: [decision 0001](../docs/decisions/0001-name-and-licence.md).
- Published the repository at https://github.com/zyakuhq/holdsend with CI: lint, types, tests, build, size budgets, gitleaks over the full history, a PII scan with a hashed denylist, a company-email check on pull request commits, and race tests against a real Postgres 16 server.
- Built all four packages, each tested:
  - `@holdsend/core`: the outbox rules, keys, written-time bounds, wire protocol and a flush scheduler. No runtime dependencies.
  - `@holdsend/server`: the idempotency store for Postgres and memory, a request handler, tombstones for deleted content, and a way to erase one person's records.
  - `@holdsend/web`: an IndexedDB store that stays atomic across tabs, one sender across tabs, auto-flush, and Background Sync helpers that say honestly whether background sending is available.
  - `@holdsend/react-native`: a store over AsyncStorage or MMKV, with guards for corrupt data and Android's size limit, and auto-flush.
- A fault-injection suite that runs thousands of random histories (lost answers, crashes, two senders, slow storage) and checks that nothing is published twice and nothing written is lost. It was checked against deliberately broken code to make sure it fails when it should.
- An independent audit found 21 issues; all are fixed or explained. A second pass the same day found 9 more, now fixed, each with a test that fails on the old code. The biggest: an item whose server never answered was retried forever without telling the person. It now waits longer between tries and, after a day of silence, asks the person. Report: [docs/audits](../docs/audits/2026-10-25-first-independent-audit.md).
- Decisions [0002](../docs/decisions/0002-core-state-model.md) to [0006](../docs/decisions).

## Ready-to-post LinkedIn post

> Today I made the first commit of HoldSend, the open-source engine our Emergent Ventures grant supports. It lets any app keep what people write while they are offline and publish it exactly once when the signal returns.
>
> The lesson from the first day surprised me. Sending later is the easy part. The hard part is knowing when you are allowed to tell someone "cancelled". Once a request has left the phone, its answer can be lost, and the post may already exist on the server. So HoldSend only cancels what never left the device, and finishes everything else with the same key.
>
> We also had the code audited twice before the end of the day. The most useful finding was a quiet one: a message whose server never answered would keep retrying forever without anyone knowing. Now, after a day of silence, HoldSend stops and asks the person.
>
> The core, the server store and the web and mobile stores are up now. Examples come next.
