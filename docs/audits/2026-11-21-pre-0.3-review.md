# Review before 0.3.0 (2026-11-21)

A separate agent that did not write the code read everything in the packages since 0.2.0 (`git diff v0.2.0..main -- packages`), ran the tests, and ran the three real-Postgres test files against a local Postgres 16 (8 of 8 passed).

It found nothing that loses an item, sends one twice, or breaks the Postgres schema or its locks.

## Findings

| # | Finding | Kind | What we did |
| --- | --- | --- | --- |
| 1 | `approve()` left `lastAttempt` in place. An item that was refused, then grew old enough to need confirmation, can only be sent again with `approve()` (`retry()` answers `not_stuck`). After approval it was back in the queue still saying `"refused"`, which tells the person that sending again will not help. | Bug, display only | Fixed: `approve()` and `retry()` share one reset that clears `lastError` and `lastAttempt`. Test added; it fails on the old code. Core is 4 bytes smaller. |
| 2 | A sender that dies during the item's last allowed attempt leaves no `lastAttempt`: no other sender takes the item over, so nothing records the lost answer. `statusOf` shows `stuck` while `state` is still `"sending"`. | Docs said every such item has a reason | Documented, not changed in code: the case is rare (answers that never come do not use up attempts, only a dead sender does), `statusOf` already shows it as stuck, and the core is close to its size budget. docs/protocol.md and the field's doc comment say to show it like `"no_answer"`. A test pins the behaviour. |
| 3 | The test for clearing `lastAttempt` covered `retry()` only. | Weak test | Covered by the test for finding 1. |

## Checked and found correct

`deferredOffline` (set offline at the start and partway through, not set for items waiting for a person, in a retry delay or of another owner, merged across passes, read by web Background Sync and `runBackgroundFlush`); `sendNow` (clears only retry delays, keys never change, claims still prevent a second send); `postgresSchema` on Postgres 16 (a re-run while a read transaction is open succeeds under a short `lock_timeout` for plain, schema-qualified and mixed-case names; the README's `SET LOCAL lock_timeout` does not stay on a pooled connection; two instances starting at once both succeed; a missing column and indexes are added back); the `DraftState.log` move and the type-only changes match the CHANGELOG.

This is not the final audit before 1.0, which comes after 0.3.0.
