## Done today

- The 0.3 upgrade guide lists three behaviour changes it had missed ([#92](https://github.com/zyakuhq/holdsend/pull/92)). [upgrading.md](../docs/upgrading.md) named only the type changes, so TypeScript would not point anyone at these: `postgresSchema()` must now be sent whole, `onBackgroundSync` rejects after an offline flush so the browser may try again, and `runBackgroundFlush` says `waiting` instead of `done` in that case. The changelog's unreleased section now opens with a summary, ready to become the 0.3.0 release notes.
- Tests load `@holdsend/core/drafts` from source (same pull request). The test setup had no alias for that subpath, so the server's draft tests used core's built copy: on a fresh checkout they failed before a build, and after a source change they tested old code. Found by running the never-twice soak right after `npm ci`. A new test fails when any published entry point has no alias.
  - Checked: the new test fails without the alias; the never-twice soak passes at 3000 runs.

## LinkedIn post
Before releasing HoldSend 0.3, I reread our upgrade guide and found it only listed type changes. That is the part TypeScript already catches for you. The changes it missed were behaviour: a schema string that must now be sent in one piece, and a background sync that now asks the browser to try again when the phone went offline mid-send. No compiler flags those, so they are the ones a guide exists for. They are written down now, with what to check in your app. While testing, I also found that some server tests were running an old built copy of our core package instead of the source; a new test stops that from coming back. https://github.com/zyakuhq/holdsend
