## Ready-to-post LinkedIn post

> Today I settled a small question in HoldSend, our open-source engine for writing offline: if one queued message fails, should the ones behind it wait?
>
> For a blog post, maybe. For an emergency message, no. One stuck message must not block a person's whole queue. So a flush tries items oldest first, and carries on past a retry. The cost is that order is not guaranteed, so the docs now say so and suggest showing the written time or a sequence number.
>
> The lesson: write down what you do not promise as clearly as what you do.
