# Update: 2026-10-29

## What got done today

- Emergency messages, first part: a short text gets out once when the signal returns. The first message goes by itself, later ones wait for the person, the same words tapped again count as one message, a message waiting for a day asks first, and there's an SMS hand-off link. It is a delivery aid, not an emergency service. Not released yet: [decision 0007](../docs/decisions/0007-emergency-messages.md), [guide](../docs/emergency.md).
- A separate reviewer went through it before merge and found eleven issues. The two serious ones: a service worker sending from the same queue ignored the one-day rule, and a message the server had refused swallowed new taps. Both are fixed, along with the rest. Each new test was checked to fail without its fix.
- Every package now exports `./package.json`, which some tools read.
- The PII scan now allows only the North American numbers reserved for fiction (555-0100 to 555-0199). Real numbers from other countries are still caught.

## Ready-to-post LinkedIn post

> Today I started the emergency part of HoldSend, our open-source engine for writing offline.
>
> The hard question wasn't how to send. It was which messages should go by themselves. Someone with no signal often writes several messages, each more urgent or more out of date than the last. Sending all of them the moment the signal returns, possibly hours later, can scare the people who receive them more than it helps.
>
> So the first message goes by itself, and the rest wait for the person to press Send. Tapping Send five times in panic counts as one message. A message that has waited a day asks before going.
>
> It's not released yet, and it's a delivery aid, not an emergency service.
>
> github.com/zyakuhq/holdsend
>
